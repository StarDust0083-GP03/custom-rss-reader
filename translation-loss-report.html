翻译内容丢失 · 排查报告

日期:2026-11-13 对象:custom-rss-reader(实际运行的应用) 结论:7 处已验证缺陷,均可从上游仓库移植修复

结论摘要

实际在用的应用是 ~/Documents/custom-rss-reader(10 月 31 日构建的 debug 版),而不是 ~/Documents/code/rss-reader。 两个项目共用同一个数据库 ~/.rss-reader/rss_reader.db。10 月 31 日之后所有翻译记录都由 fork 写入(数据库中 translated_source_hash/translated_model/translated_prompt_version 三列为空,是 fork 版 update_translation 的特征;上游版本会写入这三列)。

fork 的代码停在 9 月 2 日的 9a8934c + 阅读功能改动,不包含上游 9 月 13 日(a3c9725)与 9 月 19 日(136c390)提交的整组翻译健壮性修复:段落标记(###P<n>###)、折叠检测与递归恢复、截断拒绝、双语结构校验、强制重译不再先删旧译文、前端以命令返回值为准。我用真实文章 + 真实 MiniMax API 对 fork 的管线做了端到端实测,以下缺陷全部复现。

你描述的症状可以完全对应:

  • "只保留最后一部分翻译,失败的部分丢失" —— 块级失败时整个 run 作废(D7),强制重译先删旧译文(D5),截断/空块静默丢失(D2/D3);
  • "翻译不完整、文章读不了" —— 模型把整块折叠成一对、回显原文时丢段落,无检测无恢复,坏结果被缓存 3 天(D1/D4);
  • "可能与图片和标记有关" —— 译文侧图片回显清理、Markdown 标记(**、###)在渲染层会转换形态,这部分已逐层验证不是丢内容的原因;真正丢内容发生在翻译管线与缓存,与图片无关。

缺陷清单(按严重程度)

P0D1 · 段落折叠无检测、无恢复,模型丢掉的段落永久丢失

src-tauri/src/ai/service.rs — translate_block(第 471 行起)

MiniMax-M2.7-highspeed 的输出结构不稳定。实测同一篇文章(10 块、每块 3000 字符):一次运行 10 个块全部折叠成 1 对(20–46 个段落被合并成一个 translation-paragraph),另一次运行却返回逐段 352 对。折叠时模型回显原文还会漏掉段落(实测第 9 块漏了 1 段;9716 的缓存译文也漏了引用段落)。

fork 没有任何折叠检测,坏答案直接 Ok → 入库 → 缓存 3 天。双语视图变成"整块原文 + 整块译文",配对关系被破坏;漏掉的段落读者永远看不到。

实测证据:block 1: OK len=3990 paras=34 pairs=1(10/10 块均如此);上游仓库 ai/service.rs 注释原文:"a real 13-paragraph article came back as a single pair, which renders as 'all the original, then all the translation'" —— 正是你看到的现象。

上游已有修复:mark_paragraphs 给每个段落编号 ###P<n>###,collapses_paragraphs 检测,translate_with_recovery 对折叠/截断的块在段落边界对半拆分重译(MAX_SPLIT_DEPTH=2)。实测上游管线对同一篇 29K 文章:10 块全部恢复逐段配对,0 段缺失。

P0D2 · 截断响应被当作成功,半截译文入库并缓存

src-tauri/src/ai/service.rs — send_request_with_priority(第 303 行起)

fork 完全不检查 finish_reason。响应在 max_tokens 处被截断时(finish_reason=length),返回的是未闭合的半个双语对,例如实测:

finish_reason: length
content 尾部: ...<div class="paragraph-original">The quick brown   ← 译文名存实亡,original 未闭合

该块被当作成功:推入 chunks、发进度事件、拼进全文、写入数据库并缓存 3 天。该段落在文章里就是"只有原文没有译文",或整个块缺失。只有最后一个块(通常最短)侥幸完整时,整篇译文就"只剩最后一部分"。

上游已有修复:is_truncation_error + Truncation::Reject,截断视为失败请求,进入拆分恢复;注释写明"Returning it as success cached half a paragraph as the article's finished translation"。

P1D3 · strip_think_tags 遇到未闭合 <think> 把整个回答丢成空串

src-tauri/src/ai/service.rs — strip_think_tags(第 1261 行)

当响应在思维链内部被截断(<think> 没有闭合标签)时,该函数把从 <think> 起的所有内容全部丢弃,返回 Ok("")。空块被前端静默跳过(else if (html_chunk) 对空串不成立),该块的正文一个字都不会出现在译文里,而整个 run 仍"成功完成"、提示 Translation complete、入库缓存。多个块如此时即"大部分内容缺失"。

上游已有修复:validate_bilingual_block 拒绝空回答/空译文侧,空回答不再进入缓存。

P1D4 · 无双语结构校验,拒答/复读也会被缓存为"译文"

src-tauri/src/ai/service.rs — 缺少 validate_bilingual_block

fork 不校验回答是否真的是双语对(必须同时含 paragraph-original 与 paragraph-translated、译文侧非空)。模型拒答、只回显原文、或输出无 paragraph-translated 的残块时,都被原样缓存。上游的 validate_bilingual_block 正是为此而生。

P1D5 · 强制重译先删旧译文,重译失败后文章什么都不剩

src-tauri/src/commands/streaming.rs — translate_streaming_inner 第 130 行

if force {
    if let Err(e) = state.feed_repo.update_translation(item_id, None, "").await { ... }
}

右键强制重译会先把数据库里的旧译文清空再开始。配合 D7(任一块失败则整个 run 失败、不落库),重译失败后旧译文也没了——"失败的部分丢失,文章读不了"。前端 retranslateItem 同样先 item.translated_content = null。

上游已有修复(136c390):"A forced run no longer deletes the stored translation first: the last good result stays available until the replacement actually commits."

P1D6 · 前端丢弃命令返回值,事件丢失时译文残缺且无法补救

src/features/ai.ts — translateItem(第 244–252 行)

if (htmlContent) { await invoke<string>("translate_html_content_streaming", {...}); }
else { await invoke<string>("translate_item_bilingual_streaming", {...}); }
// 返回值被丢弃

后端命令的返回值是权威的完整文档,前端却只依赖进度事件累积 inProgressContent。任何一个事件缺失/为空(见 D2/D3),会话内的译文就永久缺块——哪怕数据库里存的是完整的。上游的 reconcileCompletedRun 在命令返回后用返回值兜底校正。

P2D7 · 任一块失败即全盘作废:直播内容清空、循环中断、无处续传

src-tauri/src/commands/streaming.rs(第 214 行 break)+ src/features/ai.ts(catch 分支)

块循环遇到第一个错误就 break,返回 Err;前端 catch 把 inProgressContent = null、useTranslation = false——用户眼看着逐块流出的译文瞬间全部消失,退回原文视图。重试永远从第 1 块重来;只要某个块稳定失败(如长段截断),文章就永远翻译不出来。上游通过 D1/D2 的恢复机制把失败消弭在块内部,失败变得罕见。

P2D8 · 缓存只看年龄,无源文指纹

src-tauri/src/commands/streaming.rs — lookup_cached_translation + feed_item_repo.update_translation

fork 的 update_translation 不写 translated_source_hash / translated_model / translated_prompt_version,缓存命中只判断 3 天有效期。文章的 content_md 被网站抓取刷新后,旧译文照样命中;换模型、换提示词也不失效。上游以三列指纹判定,不匹配即重译。

P3D9 · 杂项

  • 失败 toast 提示 Check ~/.rss-reader/ai_errors.log,但代码里没有任何地方写这个文件(主仓库、fork 均未写)。
  • fork 的 send_request 用无上限的 response.json(),上游已加 4MB read_bounded。
  • 分块恢复时上游固定以 is_html=false 重建提示词(上游自身的小瑕疵,顺手可修)。
